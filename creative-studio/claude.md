# Project Feature Tracking

After every non-trivial, non-UI feature change, update `features.txt` with a concise, high-level summary of the product's current capabilities. Keep it current rather than maintaining a changelog, and remove descriptions of features that no longer exist.

Do not add UI controls, navigation items, sample records, labels, or advertised capabilities solely to make a mockup appear complete. Every visible interactive element must perform the action it represents. If a future capability is not implemented, keep it out of the UI rather than presenting a placeholder.
